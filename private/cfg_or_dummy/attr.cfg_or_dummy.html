cfg_or_dummy

Attribute Macro cfg_or_dummy 

Source 
#[cfg_or_dummy]
Expand description

Adds a condition-specific implementation and a dummy implementation for a free function.

The attribute accepts one cfg metadata item, such as target_arch = "aarch64" or any(target_arch = "aarch64", target_arch = "riscv64"). For a function annotated with #[cfg_or_dummy(condition)], the macro emits two conditional definitions:

  • #[cfg(condition)] emits the original function and its implementation.
  • #[cfg(not(condition))] emits a dummy function with the same interface.

Only the definition whose condition matches the current configuration is compiled. The dummy preserves the function’s signature, visibility, attributes, generics, ABI, safety, and return type. Its body is unreachable, so it does not implement the target-specific operation.

§Documentation builds

This attribute is intended for functions inside modules enabled with #[cfg(any(condition, doc))]. During a documentation build for another target, doc keeps the module available. A function marked only with #[cfg(condition)] would disappear from the generated documentation, while an unconditionally compiled function could fail because its body refers to target-specific code. The dummy keeps the function interface available while avoiding that body.

The generated definitions receive doc(cfg(condition)), so rustdoc records the condition under which the real implementation is available.

§Examples

Keeps an x86-64 inline-assembly implementation available in rustdoc:

#[cfg(any(target_arch = "x86_64", doc))]
pub mod cpu {
    use cfg_or_dummy::cfg_or_dummy;

    #[cfg_or_dummy(target_arch = "x86_64")]
    pub fn pause() {
        // SAFETY: `pause` has no memory or stack effects exposed to Rust.
        unsafe {
            core::arch::asm!("pause", options(nomem, nostack, preserves_flags));
        }
    }
}

#[cfg(target_arch = "x86_64")]
cpu::pause();

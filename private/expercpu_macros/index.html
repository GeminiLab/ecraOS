§expercpu_macros

expercpu_macros implements the procedural macros used by expercpu. It is an implementation crate and applications should depend on expercpu directly.

The macro crate is derived from the macro side of ArceOS’s percpu implementation. expercpu_macros retains the upstream def_percpu approach while generating code for ecraOS’s linker symbols, address types, non-contiguous per-CPU areas, host-test backend, remote-area interface, preemption feature, and AArch64 EL1 or EL2 register selection. The remote-area interface is only one part of that non-contiguous-area design.

§def_percpu

The #[def_percpu] attribute accepts a static definition and generates three pieces:

  • a hidden static value in the .percpu linker section that acts as the initial image
  • a zero-sized wrapper type with address, pointer, reference, and reset operations
  • a static accessor with the visibility and attributes of the input definition

Primitive integer types also receive optimized current-CPU read and write operations. The remote-access feature adds raw remote pointer and reference operations. The preempt feature adds the no-preemption guard used by safe current-CPU operations.

The generated code combines the per-CPU symbol offset with the current CPU area base. It reads the base from the architecture-specific register on the current CPU. Remote operations obtain another CPU area through the interface generated by expercpu.

§Internal interface

The crate also provides the hidden percpu_symbol_vma function-like macro. The expercpu runtime uses it to resolve linker symbols such as _percpu_start and _percpu_end. This macro is an implementation detail and is not intended for direct use.

The generated AArch64 code uses TPIDR_EL1 by default and TPIDR_EL2 when the arm-el2 feature is enabled. The generated instruction sequences support x86-64, RISC-V 64, and AArch64.

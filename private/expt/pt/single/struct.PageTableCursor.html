Expand description

A mutating cursor over a PageTable.

The mutable borrow excludes other Rust mutations through the borrowed value. Callers must prevent hardware accesses to affected mappings and tables until updates and cleanup finish, select a suitable TlbFlusher, and ensure that no other multi-level page table manages the same table frames.

See PageTableCursorLike for mutation, table-frame deallocation, and partial-failure behavior. PendingCleanup performs pending invalidations through F.

fn iter_pages_in_range<C>( &mut self, range: AddrRange<M::VirtAddr>, max_page_level: Option<usize>, replace_table: bool, c: C, ) -> PagingResult<M::VirtAddr>
where C: FnMut(usize, usize, M::VirtAddr, &mut PTE) -> PagingResult<M::VirtAddr, TlbFlush<M::VirtAddr>>,

Splits a range into the largest supported pages and invokes a callback for each.

The function removes current mappings from the range and calls c for the entry representing each selected page.

The callback parameters are the entry level, its table index, the page’s starting virtual address, and a mutable reference to the entry. Level 0 is the lowest level and M::LEVELS - 1 is the highest.

Before invoking the callback, an existing leaf is cleared. A child table’s subtree is either deallocated and its descriptor cleared, or its descendant leaves are cleared with table descriptors retained, according to the replacement argument. Huge mappings are split when traversal must descend to a lower level.

The input range is expanded outward to the page size of the lowest level.

max_page_level is the maximum supported page level, None means using the maximum page level specified by the metadata.

pub fn map( &mut self, vaddr: M::VirtAddr, paddr: PhysAddr, size: usize, flags: MappingFlags, ) -> PagingResult<M::VirtAddr>

Maps a virtual address range to a physical address range.

The virtual range expands outward to base-page boundaries, and paddr is rounded down independently. Each resulting page maps at a constant offset from the aligned virtual start to the aligned physical start. Existing mappings in the expanded range are replaced. For example, with 4 KiB base pages, (vaddr = 0x1003, paddr = 0x8005, size = 0x1000) maps virtual 0x1000..0x3000 to physical 0x8000..0xa000.

A zero-size request succeeds without validating addresses or recording cleanup. An overflowing virtual endpoint or outward alignment fails with PagingError::NonCanonical.

See PageTableCursorLike::map for leaf selection, cleanup, and partial-failure behavior.

Source

pub fn unmap( &mut self, vaddr: M::VirtAddr, size: usize, ) -> PagingResult<M::VirtAddr>

Removes mappings from a virtual address range.

The range expands outward to base-page boundaries. Existing huge mappings may be split or cleared as needed, and any affected TLB entries are recorded for this cursor’s next cleanup.

A zero-size request succeeds without validating addresses or recording cleanup.

Data frames are not deallocated. Intermediate tables remain allocated, and absent paths may allocate tables. An error can leave earlier changes applied. See PageTableCursorLike::unmap for cleanup behavior.

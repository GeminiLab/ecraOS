Expand description

The common interface for concrete multi-level page table types.

This trait is primarily used to constrain the behavior of single::PageTable and dual::DualPageTable. Most callers should use one of those concrete types, or crate::opaque::OpaquePageTable when runtime type erasure is required.

Required Associated Types§

Source

type VirtAddr: VirtAddr

The semantic virtual-address type accepted by this multi-level page table.

The type determines the addresses accepted by mapping operations.

Source

type Root: Copy

The value identifying one or more page table roots.

Copying this value does not change the table frames’ lifetime. Therefore, the user must not use this value after dropping the page table hierarchy.

Source

type Allocator: PageAllocator

The allocator for table frames.

Allocations, physical-address translation, and deallocation use this type.

Source

type TlbFlusher: TlbFlusher<Self::VirtAddr>

The TLB flusher for this page table hierarchy.

TLB invalidations are performed using this type.

Source

type Cursor<'a>: PageTableCursorLike<VirtAddr = Self::VirtAddr, Allocator = Self::Allocator, PageTable = Self> where Self: 'a

The cursor used to mutate this page table hierarchy.

The cursor borrows the multi-level page table mutably during mutation.

Required Methods§

Source

unsafe fn new_at(root: Self::Root) -> Self

Constructs a multi-level page table from an existing page table hierarchy.

§Safety

The root must satisfy the requirements of PageTable::new_at for a single-root implementation, or DualPageTable::new_at for a dual-root implementation.

Source

fn new_alloc() -> PagingResult<Self::VirtAddr, Self>

Allocates and initializes a multi-level page table through the selected allocator.

Only the root page tables are allocated initially. Child page tables are allocated as needed by cursor operations.

Source

fn root(&self) -> Self::Root

Returns the root identifier without changing the table frames’ lifetime.

The returned physical address (or pair of physical addresses for dual-root multi-level page tables) must not be used after dropping this value.

Source

fn leak(self) -> Self::Root

Consumes the multi-level page table without deallocating its table frames.

Another multi-level page table can use the returned root if its allocator can access and deallocate every existing table frame. Otherwise, the caller must arrange their deallocation.

Source

fn cursor(&mut self) -> Self::Cursor<'_>

Creates a cursor for batched mutations.

See PageTableCursorLike for batching and cleanup behavior.

Dyn Compatibility§

This trait is not dyn compatible.

In older versions of Rust, dyn compatibility was called "object safety".

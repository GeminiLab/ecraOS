Expand description

A dual-root multi-level page table for lower and upper virtual-address ranges.

The type-level constraints prevent combining symmetric roots or roots with different virtual-address types. The hierarchies may use different geometries and entry types. Both must form valid trees with disjoint table-frame allocations. Both roots use AL for their table frames, and F handles cleanup for both. See table-frame lifetime and the safety requirements for page table updates.

Each map and unmap operation is routed to the root selected by its starting virtual address. An individual range must remain within one canonical side and cannot cross the gap between the lower and upper ranges.

pub unsafe fn new_at(root: DualPageTableRoot) -> Self

Constructs a dual-root multi-level page table from existing lower and upper hierarchies.

This function does not inspect either root. The caller must ensure that both physical addresses identify valid page table roots for their respective metadata types.

§Safety

Each root must satisfy PageTable::new_at. The two page table hierarchies must not share table frames.

pub fn new_alloc() -> PagingResult<A, Self>
where [(); { _ }]: Sized,

Allocates and initializes both root page tables through AL.

The roots have the size required by the highest level in ML and MU and are zero-initialized before the value is returned. If the upper-root allocation fails, the lower root is deallocated.

Source

pub fn leak(self) -> DualPageTableRoot

Consumes the value without deallocating table frames and returns both roots.

Another dual-root multi-level page table can use the roots if its allocator can access and deallocate every table frame. Otherwise, the caller must arrange their deallocation. The allocator type may differ from AL if those requirements hold.

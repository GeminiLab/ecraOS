1//! Host test compile guard.
2//!
3//! To allow running unit tests on host, the `host-test` feature is introduced to notify lower-level
4//! modules that they are running in a host test environment (`#[cfg(test)]` does not work on
5//! dependencies).
6//!
7//! Unit tests require the `host-test` feature to be enabled, and vice versa. This module enforces
8//! this requirement at compile time.
9//!
10//! For best compatibility with `rust-analyzer`, `#[cfg(test)]` should be used on items that should
11//! only be included in unit tests (instead of `#[cfg(feature = "host-test")]`), and
12//! `#[cfg(not(feature = "host-test"))]` should be used on items that should only be included in the
13//! real kernel build (instead of `#[cfg(not(test))]`).
14//!
15//! Such patterns ensure the maximum code coverage of `rust-analyzer`.
16//!
17//! When it causes conflicts, use `#[cfg(feature = "host-test")]` instead of `#[cfg(test)]`.
18//!
19//! This rule applies only to the `ecraos` crate, lower-level modules should always use the
20//! `host-test` feature.
21
22#[cfg(all(test, not(feature = "host-test"), not(rust_analyzer)))]
23compile_error!("`host-test` feature must be enabled for unit tests on host");
24
25#[cfg(all(not(test), not(doc), feature = "host-test"))]
26compile_error!("`host-test` feature must not be enabled for real kernel build");
27
28#[cfg(all(feature = "host-test", not(target_os = "linux")))]
29compile_error!("host-test feature is only supported on Linux currently");

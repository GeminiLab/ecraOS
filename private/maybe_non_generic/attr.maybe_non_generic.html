Attribute Macro maybe_non_generic 

Source 
#[maybe_non_generic]
Expand description

Generates a copy of a generic function with selected generic parameters replaced.

The attribute applies to a generic function with a body, which may be a free function, a function in an impl block, or a default method of a trait. The original function is emitted unchanged. The copy uses the name given by the first attribute argument, and each replaced generic parameter becomes a trailing function parameter. A const generic becomes a runtime value, and a type generic becomes a value that stands in for the type, such as a table of function pointers.

For example, the following copy takes the number of summed values as its last argument:

use maybe_non_generic::maybe_non_generic;

#[maybe_non_generic(sum_dyn, const(N => count: usize))]
fn sum<const N: usize>(values: &[u32]) -> u32 {
    values.iter().take(N).sum()
}

assert_eq!(sum::<2>(&[1, 2, 3]), 3);
assert_eq!(sum_dyn(&[1, 2, 3], 2), 3);

§Syntax

The first argument names the copy:

#[maybe_non_generic(copy_name, argument, ...)]

The name can be followed by any number of comma-separated arguments, and a trailing comma is allowed. Each argument has one of the following forms:

  • const(N => n: T) replaces the const generic N with the trailing parameter n: T.
  • type(H => h: T) replaces the type generic H with the trailing parameter h: T.
  • fn(path::f => path::g) renames calls to the function path path::f in the copied body.
  • fn(receiver.f => receiver.g) renames method calls receiver.f(...) in the copied body.
  • attr(...) adds the attribute #[...] to the copy.
  • dont_copy_attr stops the attributes of the original function from being copied.

§Generic parameter replacement

Each const(...) or type(...) argument names one generic parameter of the function and the parameter that replaces it. The arguments must follow the order of the generic parameters in the function signature, and the new parameters are appended in that order. Generic parameters that are not replaced, including lifetimes, stay on the copy. Bounds and where predicates that mention a replaced parameter are removed.

§Body rewrites

The body of the copy is rewritten as follows:

  • A const parameter N used as an expression becomes n.
  • A call H::f(args) becomes (h.f)(args), and an expression H::ITEM becomes h.ITEM. The function-pointer tables generated by dyn_static_traits have this shape.
  • In a call with a turbofish, such as f::<N, H>(args), replaced generic arguments are removed from the last path segment and appended to the call arguments. A const argument passes n, and a type argument passes ::core::clone::Clone::clone(&h), so the type of h must implement Clone. References and dyn_static_traits tables do.

Nested items, such as functions declared inside the body, are left unchanged, because they cannot use the generic parameters of the outer function.

The original callee still expects its generic arguments, so a call that passes replaced arguments usually also needs a fn(...) rename to the callee’s own copy. The following example replaces a clock type with a table generated by dyn_static_traits and renames the inner call:

use dyn_static_traits::dyn_static_traits;
use maybe_non_generic::maybe_non_generic;

#[dyn_static_traits(DynClock)]
trait Clock {
    fn now() -> u64;
}

struct BootClock;

impl Clock for BootClock {
    fn now() -> u64 {
        100
    }
}

#[maybe_non_generic(elapsed_dyn, type(C => clock: &DynClock))]
fn elapsed<C: Clock>(start: u64) -> u64 {
    C::now() - start
}

#[maybe_non_generic(
    scaled_elapsed_dyn,
    const(N => factor: u64),
    type(C => clock: &DynClock),
    fn(elapsed => elapsed_dyn),
)]
fn scaled_elapsed<const N: u64, C: Clock>(start: u64) -> u64 {
    elapsed::<C>(start) * N
}

let clock = DynClock::new::<BootClock>();
assert_eq!(scaled_elapsed::<2, BootClock>(40), 120);
assert_eq!(scaled_elapsed_dyn(40, 2, &clock), 120);

In scaled_elapsed_dyn, the call elapsed::<C>(start) becomes elapsed_dyn(start, ::core::clone::Clone::clone(&clock)), and N becomes factor.

§Call renaming

A fn(path => path) argument renames calls whose function path has the same segment names as the source path. Generic arguments are ignored while matching, and arguments that are not replaced are kept, so fn(Table::size => Table::size_dyn) also matches Table::<M>::size::<L>(...). Both paths must have the same number of segments.

A fn(receiver.method => receiver.method) argument renames method calls whose receiver has the same tokens as the given receiver, such as self.clear(...). The source and target receivers must be the same. Replaced generic arguments in the method turbofish are appended to the call arguments.

The following example renames an associated function call and a method call in an impl block:

use maybe_non_generic::maybe_non_generic;

struct Table {
    entries: usize,
}

impl Table {
    #[maybe_non_generic(entry_size_dyn, const(LEVEL => level: usize))]
    fn entry_size<const LEVEL: usize>() -> usize {
        8 << LEVEL
    }

    #[maybe_non_generic(
        bytes_dyn,
        const(LEVEL => level: usize),
        fn(Self::entry_size => Self::entry_size_dyn),
    )]
    fn bytes<const LEVEL: usize>(&self) -> usize {
        Self::entry_size::<LEVEL>() * self.entries
    }

    #[maybe_non_generic(
        double_bytes_dyn,
        const(LEVEL => level: usize),
        fn(self.bytes => self.bytes_dyn),
    )]
    fn double_bytes<const LEVEL: usize>(&self) -> usize {
        self.bytes::<LEVEL>() * 2
    }
}

let table = Table { entries: 4 };
assert_eq!(table.bytes::<1>(), 64);
assert_eq!(table.bytes_dyn(1), 64);
assert_eq!(table.double_bytes::<1>(), 128);
assert_eq!(table.double_bytes_dyn(1), 128);

§Attributes

The copy receives the attributes of the original function, including doc comments, followed by the attributes from attr(...) arguments. #[maybe_non_generic] attributes are never copied, so stacking several of them on one function generates one copy per attribute. With dont_copy_attr, only the attr(...) attributes are applied.

The following example generates two copies of one function with different doc comments:

use maybe_non_generic::maybe_non_generic;

/// Sums the first `N` values.
#[maybe_non_generic(sum_dyn, const(N => count: usize))]
#[maybe_non_generic(
    sum_counted,
    const(N => count: usize),
    dont_copy_attr,
    attr(doc = "Sums the first `count` values."),
)]
fn sum<const N: usize>(values: &[u32]) -> u32 {
    values.iter().take(N).sum()
}

assert_eq!(sum_dyn(&[1, 2, 3], 2), 3);
assert_eq!(sum_counted(&[1, 2, 3], 2), 3);

sum_dyn receives the doc comment of sum, while sum_counted receives only the doc comment from attr(...).

§Limitations

The macro reports a compile error instead of generating a copy that might still depend on a replaced parameter. It rejects:

  • items other than functions with a body,
  • functions without generic parameters,
  • replacements that name a missing generic parameter, a parameter of the other kind, or the same parameter twice,
  • generated parameter names that are already bound by a function parameter or in the body,
  • function parameter types or a return type that still mention a replaced parameter,
  • generic arguments on an associated function of a replaced type, such as H::f::<T>(),
  • replaced parameters that remain in the body after rewriting, for example in a type annotation, in a generic argument expression such as { N - 1 }, or in a qualified path such as <H as Trait>::f().

The macro cannot see inside some syntax, so it treats that syntax as a remaining use of a replaced parameter. The body of the copy therefore cannot contain macro invocations, or patterns with literals, ranges, or paths, such as 0, 1..=9, or Ordering::Less. This applies even when the syntax does not mention a replaced parameter.

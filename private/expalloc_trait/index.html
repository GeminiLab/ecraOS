§expalloc_trait

expalloc_trait provides PageAllocator, a static interface for allocating physically contiguous page frames, releasing them, and accessing them through virtual addresses. Generic code selects an implementation through a type parameter. The generated DynPageAllocator table provides runtime selection through function pointers.

The crate is no_std and does not supply an allocator implementation. Physical and virtual addresses use PhysAddr and VirtAddr from memory_addr.

§Usage

Implement the four required functions of PageAllocator for an allocator type. This example represents an empty pool, so allocation always fails and neither deallocation nor translation has a valid input:

use expalloc_trait::{DynPageAllocator, PageAllocator};
use memory_addr::{PhysAddr, VirtAddr};

struct EmptyAllocator;

impl PageAllocator for EmptyAllocator {
    fn page_size_shift() -> usize {
        12
    }

    fn alloc_frames(_page_count: usize) -> Option<PhysAddr> {
        None
    }

    fn dealloc_frames(_addr: PhysAddr, _page_count: usize) {
        panic!("the empty allocator has no allocations");
    }

    fn phys_to_virt(_addr: PhysAddr) -> VirtAddr {
        panic!("the empty allocator has no mapped memory");
    }
}

assert_eq!(EmptyAllocator::page_size_shift(), 12);
assert_eq!(EmptyAllocator::alloc_frame(), None);

let allocator = DynPageAllocator::new::<EmptyAllocator>();
assert_eq!((allocator.page_size_shift)(), 12);
assert_eq!((allocator.alloc_frames_of_size)(4097), None);

Generic code can allocate storage and obtain its accessible address without knowing the concrete allocator:

use expalloc_trait::PageAllocator;
use memory_addr::{PhysAddr, VirtAddr};

fn allocate_buffer<A: PageAllocator>(size: usize) -> Option<(PhysAddr, VirtAddr)> {
    let physical = A::alloc_frames_of_size(size)?;
    let accessible = A::phys_to_virt(physical);
    Some((physical, accessible))
}

The caller retains responsibility for the allocation. After all accesses have ended, it releases the storage with A::dealloc_frames_of_size(physical, size) using the original byte size.

§Default methods and contracts

PageAllocator::alloc_frame and PageAllocator::dealloc_frame delegate to the corresponding frame-count functions with a count of one. The default PageAllocator::alloc_frames_of_size and PageAllocator::dealloc_frames_of_size round byte sizes up to whole pages. For example, with 4 KiB pages, 4097 bytes require two frames. A zero byte size is forwarded as a zero page count, whose behavior is determined by the implementation.

An implementation may override the provided methods, including tracking the original byte size. Callers should pair the byte-size methods with the original size even when a different size would round to the same page count. See PageAllocator and its associated functions for the page-size, allocation-lifetime, and address-access requirements.

§Runtime selection

DynPageAllocator::new stores the selected implementation’s associated functions, including overrides of the default methods. Tables constructed from different implementations have the same type and can be selected at runtime. Call a field with parentheses, such as (allocator.alloc_frame)(), because each field is a function pointer.

The table is generated by dyn_static_traits::dyn_static_traits. Its fields link to the corresponding PageAllocator functions and retain their contracts.

Physical memory region management.

§The table

This module maintains the kernel’s global table of physical memory regions, as a list of PhysMemoryRegions. Each PhysMemoryRegion describes a physical address range, its flags, and a description. Regions are nonempty, sorted by physical address, and non-overlapping. Their boundaries are of byte precision.

The table itself is not public, it should be accessed through the methods provided in this module. The table is protected by a read-write lock, so concurrent read-only access is possible.

§Initialization

The table is initialized during early boot with a fixed capacity, from the platform memory information and kernel and loader reservations. After heap initialization, its storage can be switched to support additional regions without the early capacity limit, and can be extended with discovered device regions.

§Cross-module interaction

Page allocators use the table to identify usable RAM, and super::vmm uses the table to map the direct-mapping areas.

§Access

Use lock_read_phys_mem_regions and try_lock_read_phys_mem_regions to inspect the table under a shared read lock.

Use lock_write_phys_mem_regions and try_lock_write_phys_mem_regions to modify the table under an exclusive write lock, these functions are unsafe because they require the caller to preserve the region invariants. These functions will NOT update the direct-mapping areas or the page allocator.

The table may be appended (and overwritten) with add_and_map_phys_regions. Adding new regions automatically maps them to the direct-mapping area (and identity-maps them if the identity mappings are still active). Therefore, adding new regions is a relatively expensive operation, so it is recommended to add regions in batches.

Removing regions is not supported yet.

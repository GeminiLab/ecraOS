9/// Get the shared memory size in number of bytes for sending and receiving messages.
10///
11/// The shared memory size returned by the SBI implementation MUST satisfy the following requirements:
12/// - The shared memory size MUST be same for all HARTs.
13/// - The shared memory size MUST be at least 4096 bytes.
14/// - The shared memory size MUST be multiple of 4096 bytes.
15/// - The shared memory size MUST not be less than the biggest MSG_DATA_MAX_LEN attribute value across all MPXY channels.
16///
17/// # Return value
18///
19/// This function always returns `SbiRet::success()` in `SbiRet.error` and it will return the shared memory size.
20#[doc(alias = "sbi_mpxy_get_shmem_size")]
21#[inline]
22pub fn mpxy_get_shmem_size() -> usize {
23    sbi_call_0(EID_MPXY, GET_SHMEM_SIZE).value
24}

26/// Set the shared memory for sending and receiving messages on the calling hart.
27///
28/// # Parameters
29///
30/// - `shmem`: shared memory pointer.
31///
32/// If `shmem` is not all-ones bitwise then `shmem` specifies the bits of the shared memory physical base address.
33/// The `shmem` MUST be `4096` bytes aligned and the size of shared memory is assumed to be same as returned by the Get shared memory size function: mpxy_get_shmem_size().
34/// If `shmem` is all-ones bitwise then shared memory is disabled.
35///
36/// - `flags`: the parameter specifies configuration for shared memory setup and it is encoded as follows:
37///
38/// ```text
39/// flags[XLEN-1:2]: Reserved for future use and must be zero.
40/// flags[1:0]: Shared memory setup mode (Refer table below).
41/// ```
42///
43/// | Mode             | flags\[1:0\] | Description
44/// |:-----------------|:------------|:---------------------------------
45/// | OVERWRITE        | 0b00        | Ignore the current shared memory state and force setup the new shared memory based on the passed parameters.
46/// | OVERWRITE-RETURN | 0b01        | Same as `OVERWRITE` mode and additionally after the new shared memory state is enabled, the old shared memory are written in the same order to the new shared memory at offset `0x0`. This flag provide provision to software layers in the supervisor software that want to send messages using the shared memory but do not know the shared memory details that has already been setup. Those software layers can temporarily setup their own shared memory on the calling hart, send messages and then restore back the previous shared memory with the SBI implementation.
47/// | RESERVED         | 0b10 - 0b11 | Reserved for future use. Must be initialized to `0`.
48///
49/// # Return value
50///
51/// | Error code                    | Description
52/// |:------------------------------|:---------------------------------
53/// | `SbiRet::success()`           | Shared memory was set or cleared successfully.
54/// | `SbiRet::invalid_param()`     | The `flags` parameter has invalid value or the bits set are within the reserved range. Or the `shmem` parameter is not `4096` bytes aligned.
55/// | `SbiRet::invalid_address()`   | The shared memory pointed to by the `shmem` parameter does not satisfy the requirements.
56/// | `SbiRet::failed()`            | The request failed for unspecified or unknown other reasons.
57#[doc(alias = "sbi_mpxy_set_shmem")]
58#[inline]
59pub fn mpxy_set_shmem(shmem: SharedPtr<u8>, flags: usize) -> SbiRet {
60    sbi_call_3(
61        EID_MPXY,
62        SET_SHMEM,
63        shmem.phys_addr_lo(),
64        shmem.phys_addr_hi(),
65        flags,
66    )
67}

69/// Get channel IDs of the message channels accessible to the supervisor software in the shared memory of the calling hart.
70///
71/// The channel IDs are returned as an array of 32 bits unsigned integers where the `start_index` parameter specifies the array index
72/// of the first channel ID to be returned in the shared memory.
73///
74/// The SBI implementation will return channel IDs in the shared memory of the calling hart as specified by the table below:
75///
76/// | Offset            | Field                            | Description
77/// |:------------------|:---------------------------------|:---------------------------------
78/// | 0x0               | REMAINING                        | Remaining number of channel IDs.
79/// | 0x4               | RETURNED                         | Number of channel IDs (N) returned in the shared memory.
80/// | 0x8               | CHANNEL_ID [start_index + 0]     | Channel ID
81/// | 0xC               | CHANNEL_ID [start_index + 1]     | Channel ID
82/// | 0x8 + ((N-1) * 4) | CHANNEL_ID [start_index + N - 1] | Channel ID
83///
84/// The number of channel IDs returned in the shared memory are specified by the `RETURNED` field whereas the `REMAINING` field specifies the
85/// number of remaining channel IDs. If the `REMAINING` is not `0` then supervisor software can call this function again to get remaining channel
86/// IDs with `start_index` passed accordingly. The supervisor software may require multiple SBI calls to get the complete list of channel IDs
87/// depending on the `RETURNED` and `REMAINING` fields.
88///
89/// # Parameters
90///
91/// - `start_index`: specifies the array index of the first channel ID to be returned in the shared memory.
92///
93/// # Return value
94///
95/// The `SbiRet.value` is always set to zero whereas the possible error codes returned in `SbiRet.error` are below.
96///
97/// | Error code                    | Description
98/// |:------------------------------|:---------------------------------
99/// | `SbiRet::success()`           | The channel ID array has been written successfully.
100/// | `SbiRet::invalid_param()`     | `start_index` is invalid.
101/// | `SbiRet::no_shmem()`          | The shared memory setup is not done or disabled for the calling hart.
102/// | `SbiRet::denied()`            | Getting channel ID array is not allowed on the calling hart.
103/// | `SbiRet::failed()`            | The request failed for unspecified or unknown other reasons.
104#[doc(alias = "sbi_mpxy_get_channel_ids")]
105#[inline]
106pub fn mpxy_get_channel_ids(start_index: u32) -> SbiRet {
107    sbi_call_1(EID_MPXY, GET_CHANNEL_IDS, start_index as usize)
108}

110/// Read message channel attributes.
111///
112/// Supervisor software MUST call this function for the contiguous attribute range where the `base_attribute_id` is the starting index of that
113/// range and `attribute_count` is the number of attributes in the contiguous range. If there are multiple such attribute ranges then multiple
114/// calls of this function may be done from supervisor software. Supervisor software MUST read the message protocol specific attributes via
115/// separate call to this function with `base_attribute_id` and `attribute_count` without any overlap with the MPXY standard attributes.
116///
117/// # Parameters
118///
119/// - `channel_id`: specifies the message channel whereas `base_attribute_id` and `attribute_count` parameters specify the range of attribute ids to be read.
120/// - `base_attribute_id`: specifies the range of attribute ids to be read.
121/// - `attribute_count`: specifies the range of attribute ids to be read.
122///
123/// # Return value
124///
125/// Upon calling this function the message channel attribute values are returned starting from the offset `0x0` in the shared memory of the
126/// calling hart where the value of the attribute with `attribute_id = base_attribute_id + i` is available at the shared memory offset `4 * i`.
127///
128/// The possible error codes returned in `SbiRet.error` are shown below.
129///
130/// | Error code                    | Description
131/// |:------------------------------|:---------------------------------
132/// | `SbiRet::success()`           | Message channel attributes has been read successfully.
133/// | `SbiRet::invalid_param()`     | `attribute_count` is 0. Or the `attribute_count > (shared memory size)/4`. Or the `base_attribute_id` is not valid.
134/// | `SbiRet::not_supported()`     | `channel_id` is not supported or invalid.
135/// | `SbiRet::bad_range()`         | One of the attributes in the range specified by the `base_attribute_id` and `attribute_count` do not exist.
136/// | `SbiRet::no_shmem()`          | The shared memory setup is not done or disabled for calling hart.
137/// | `SbiRet::failed()`            | The request failed for unspecified or unknown other reasons.
138#[doc(alias = "sbi_mpxy_read_attributes")]
139#[inline]
140pub fn mpxy_read_attributes(
141    channel_id: u32,
142    base_attribute_id: u32,
143    attribute_count: u32,
144) -> SbiRet {
145    sbi_call_3(
146        EID_MPXY,
147        READ_ATTRIBUTE,
148        channel_id as usize,
149        base_attribute_id as usize,
150        attribute_count as usize,
151    )
152}

154/// Write message channel attributes.
155///
156/// Supervisor software MUST call this function for the contiguous attribute range where the `base_attribute_id` is the starting index of that
157/// range and `attribute_count` is the number of attributes in the contiguous range. If there are multiple such attribute ranges then multiple
158/// calls of this function may be done from supervisor software. Apart from contiguous attribute indices, supervisor software MUST also
159/// consider the attribute access permissions and attributes with RO (Read Only) access MUST be excluded from the attribute range.
160/// Supervisor software MUST write the message protocol specific attributes via separate call to this function with `base_attribute_id` and
161/// `attribute_count` without any overlap with the MPXY standard attributes.
162///
163/// Before calling this function, the supervisor software must populate the shared memory of the calling hart starting from offset `0x0` with the
164/// message channel attribute values. For each attribute with `attribute_id = base_attribute_id + i`, the corresponding value MUST be placed at
165/// the shared memory offset `4 * i`.
166///
167/// # Parameters
168///
169/// - `channel_id`: specifies the message channel whereas `base_attribute_id` and `attribute_count` parameters specify the range of attribute ids.
170/// - `base_attribute_id`: specifies the range of attribute ids.
171/// - `attribute_count`: specifies the range of attribute ids.
172///
173/// # Return value
174///
175/// The possible error codes returned in `SbiRet.error` are shown below.
176///
177/// | Error code                    | Description
178/// |:------------------------------|:---------------------------------
179/// | `SbiRet::success()`           | Message channel attributes has been written successfully.
180/// | `SbiRet::invalid_param()`     | `attribute_count` is 0. Or the `attribute_count > (shared memory size)/4`. Or the `base_attribute_id` is not valid.
181/// | `SbiRet::not_supported()`     | `channel_id` is not supported or invalid.
182/// | `SbiRet::bad_range()`         | One of the attributes in the range specified by the `base_attribute_id` and `attribute_count` do not exist or the attribute is read-only (RO). Or `base_attribute_id` and `attribute_count` result into a range which overlaps with standard and message protocol specific attributes.
183/// | `SbiRet::no_shmem()`          | The shared memory setup is not done or disabled for calling hart.
184/// | `SbiRet::denied()`            | If any attribute write dependency is not satisfied.
185/// | `SbiRet::failed()`            | The request failed for unspecified or unknown other reasons.
186#[doc(alias = "sbi_mpxy_write_attributes")]
187#[inline]
188pub fn mpxy_write_attributes(
189    channel_id: u32,
190    base_attribute_id: u32,
191    attribute_count: u32,
192) -> SbiRet {
193    sbi_call_3(
194        EID_MPXY,
195        WRITE_ATTRIBUTE,
196        channel_id as usize,
197        base_attribute_id as usize,
198        attribute_count as usize,
199    )
200}

202/// Send a message to the MPXY channel specified by the `channel_id` parameter and wait until a message response is received from the MPXY channel.
203///
204/// This function only succeeds upon receipt of a message response from the MPXY channel. In cases where complete data transfer requires
205/// multiple transmissions, the supervisor software shall send multiple messages as necessary. Details of such cases can be found in
206/// respective message protocol specifications.
207///
208/// This function is optional. If this function is implemented, the corresponding bit in the `CHANNEL_CAPABILITY` attribute is set to `1`.
209///
210/// # Parameters
211///
212/// - `channel_id`: specifies the MPXY channel.
213/// - `message_id`: specifies the message protocol specific identification of the message to be sent.
214/// - `message_data_len`: represents the length of message data in bytes which is located at the offset `0x0` in the shared memory setup by the calling hart.
215///
216/// # Return value
217///
218/// Upon calling this function the SBI implementation MUST write the response message data at the offset `0x0` in the shared memory setup by
219/// the calling hart and the number of bytes written will be returned through `SbiRet.value`. The layout of data in case of both request and
220/// response is according to the respective message protocol specification message format.
221///
222/// Upon success, this function:
223/// - Writes the message response data at offset `0x0` of the shared memory setup by the calling hart.
224/// - Returns `SbiRet::success()` in `SbiRet.error`.
225/// - Returns message response data length in `SbiRet.value`.
226///
227/// The possible error codes returned in `SbiRet.error` are shown below.
228///
229/// | Error code                    | Description
230/// |:------------------------------|:---------------------------------
231/// | `SbiRet::success()`           | Message sent and response received successfully.
232/// | `SbiRet::invalid_param()`     | The `message_data_len > MSG_DATA_MAX_LEN` for specified `channel_id`. Or the `message_data_len` is greater than the size of shared memory on the calling hart.
233/// | `SbiRet::not_supported()`     | `channel_id` is not supported or invalid. Or the message represented by the `message_id` is not supported or invalid. Or this function is not supported.
234/// | `SbiRet::no_shmem()`          | The shared memory setup is not done or disabled for calling hart.
235/// | `SbiRet::timeout()`           | Waiting for response timeout.
236/// | `SbiRet::io()`                | Failed due to I/O error.
237/// | `SbiRet::failed()`            | The request failed for unspecified or unknown other reasons.
238#[doc(alias = "sbi_mpxy_send_message_with_response")]
239#[inline]
240pub fn mpxy_send_message_with_response(
241    channel_id: u32,
242    message_id: u32,
243    message_data_len: usize,
244) -> SbiRet {
245    sbi_call_3(
246        EID_MPXY,
247        SEND_MESSAGE_WITH_RESPONSE,
248        channel_id as usize,
249        message_id as usize,
250        message_data_len,
251    )
252}

297/// Get the message protocol specific notification events on the MPXY channel specified by the `channel_id` parameter.
298///
299/// The events are message protocol specific and MUST be defined in the respective message protocol specification.
300/// The SBI implementation may support indication mechanisms like MSI or SSE to inform the supervisor software about the availability of events.
301///
302/// Depending on the message protocol implementation, a channel may support events state which includes data like number of events
303/// `RETURNED`, `REMAINING` and `LOST`. Events state data is optional, and if the message protocol implementation supports it, then the channel
304/// will have the corresponding bit set in the `CHANNEL_CAPABILITY` attribute. By default the events state is disabled and supervisor software
305/// can explicitly enable it through the `EVENTS_STATE_CONTROL` attribute.
306///
307/// This function is optional. If this function is implemented, the corresponding bit in the `CHANNEL_CAPABILITY` attribute is set to 1.
308///
309/// # Parameters
310///
311/// - `channel_id`: specifies the MPXY channel.
312///
313/// # Return value
314///
315/// In the shared memory, 16 bytes starting from offset 0x0 are used to return this state data.
316/// Shared memory layout with events state data (each field is of 4 bytes):
317///
318/// ```text
319/// Offset 0x0: REMAINING
320/// Offset 0x4: RETURNED
321/// Offset 0x8: LOST
322/// Offset 0xC: RESERVED
323/// Offset 0x10: Start of message protocol specific notification events data
324/// ```
325///
326/// The `RETURNED` field represents the number of events which are returned in the shared memory when this function is called. The `REMAINING`
327/// field represents the number of events still remaining with SBI implementation. The supervisor software may need to call this function again
328/// until the `REMAINING` field becomes `0`.
329///
330/// The `LOST` field represents the number of events which are lost due to limited buffer size managed by the message protocol
331/// implementation. Details of buffering/caching of events is specific to message protocol implementation.
332///
333/// Upon calling this function the received notification events are written by the SBI implementation at the offset `0x10` in the shared memory
334/// setup by the calling hart irrespective of events state data reporting. If events state data reporting is disabled or not supported, then the
335/// values in events state fields are undefined. The number of the bytes written to the shared memory will be returned through `SbiRet.value`
336/// which is the number of bytes starting from offset `0x10`. The layout and encoding of notification events are defined by the message
337/// protocol specification associated with the message proxy channel (`channel_id`).
338///
339/// The possible error codes returned in `SbiRet.error` are shown below.
340///
341/// | Error code                    | Description
342/// |:------------------------------|:---------------------------------
343/// | `SbiRet::success()`           | Notifications received successfully.
344/// | `SbiRet::not_supported()`     | `channel_id` is not supported or invalid. Or this function is not supported.
345/// | `SbiRet::no_shmem()`          | The shared memory setup is not done or disabled for calling hart.
346/// | `SbiRet::io()`                | Failed due to I/O error.
347/// | `SbiRet::failed()`            | The request failed for unspecified or unknown other reasons.
348#[doc(alias = "sbi_mpxy_get_notification_events")]
349#[inline]
350pub fn mpxy_get_notification_events(channel_id: u32) -> SbiRet {
351    sbi_call_1(EID_MPXY, GET_NOTIFICATION_EVENTS, channel_id as usize)
352}

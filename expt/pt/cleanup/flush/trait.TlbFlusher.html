Expand description

A TLB flushing strategy.

Implementations select the architecture and invalidation scope. A local strategy affects only the calling processor. A strategy covering remote processors must complete the required remote invalidations before returning, including the required translation and page-walk synchronization within that scope.

Callers must select a strategy suitable for the affected page table hierarchy and its hardware users. An incorrect strategy can leave stale translations or page-walk state when accesses resume under the crate-level access coordination contract. A strategy that waits for remote acknowledgement must not be invoked while the caller holds an IRQ-disabling guard, page-table lock, or allocator lock.

fn flush(addr: Option<A>)

Flushes the TLB with a specified address.

Some(addr) invalidates the mapping containing addr. None requests invalidation of all addresses within this strategy’s scope. Required synchronization completes before return.

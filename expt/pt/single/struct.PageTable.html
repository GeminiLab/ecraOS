Expand description

A single-root multi-level page table.

M describes the virtual-address layout, PTE supplies the concrete entry representation, and AL selects the allocator that is used to allocate and deallocate table frames. F selects the TlbFlusher used by cursor cleanup, including its local or remote invalidation scope. See that trait for strategy selection and synchronization requirements.

The page table hierarchy must form a valid tree.

See the crate-level documentation for table-frame deallocation and hardware-use requirements.

Use PageTable::leak to consume this value while retaining its table frames, then use PageTable::new_at to construct another value from the existing hierarchy.

pub unsafe fn new_at(paddr: PhysAddr) -> Self

Constructs a multi-level page table from an existing page table hierarchy.

This function does not inspect or initialize the root page table. Later operations access it through AL.

§Safety

The root must identify a valid tree-shaped page table hierarchy for M and PTE.

No other code may access the page table hierarchy while the PageTable lives.

The PageAllocator specified by AL must be able to manage the existing table frames.

pub const fn root(&self) -> PhysAddr

Returns the root physical address without changing the table frames’ lifetime.

Dropping the PageTable deallocates its table frames, so the caller must not use this address after dropping the PageTable.

Source

pub fn leak(self) -> PhysAddr

Consumes the PageTable without deallocating its table frames.

Another PageTable can use the root if its allocator can access and deallocate every table frame in the page table hierarchy. Otherwise, the caller must arrange their deallocation. The allocator type may differ from AL if those requirements hold. The returned address remains usable until the retained table frames are deallocated, either by the caller or by a value that adopts them.

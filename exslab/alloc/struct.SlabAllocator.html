Struct SlabAllocator

Expand description

A slab allocator over caller-supplied slab memory.

The hardware page size is fixed at construction to 4, 16, or 64 KiB. Slab sizes follow max(min(65536, slot_size * 512), page_size) and must be aligned to their complete span, where slot_size comes from the selected size class. See the crate documentation for the page counts this produces.

The caller serializes operations through the allocator and keeps slab memory alive until it is returned or every user of it has finished. Dropping the allocator does not release slab memory.

§caches: [SlabCache; 9]

Independent class states, each permanently bound to a static layout.

Hardware page size used to report slab memory requests and returns.

pub fn new(page_size: usize) -> AllocResult<Self>

Creates an empty slab allocator.

page_size must be 4, 16, or 64 KiB, and other values return AllocError::InvalidParam. No slab memory is obtained here. Each class begins empty and asks for a slab on first use.

pub fn alloc(&mut self, layout: Layout) -> AllocResult<SlabAllocResult>

Allocates an object matching the requested allocation layout.

Selects the size class from the layout and takes a slot from that class. Returns SlabAllocResult::NeedsSlab when the class has no slot available. A size or alignment above 2048 bytes returns AllocError::InvalidParam.

Source

pub unsafe fn add_slab( &mut self, class: SizeClass, base: VirtAddr, owner_cpu: u16, ) -> AllocResult

Registers slab memory for the selected size class.

The memory must be the size that Self::alloc reported for class, and the allocator takes no separate size argument because the class fixes it. A zero or misaligned base returns AllocError::InvalidParam before memory is accessed.

Registration is unsafe, so safe code cannot register an arbitrary address as slab memory.

ⓘ
use exslab::{SizeClass, SlabAllocator};
use memory_addr::va;

let mut allocator = SlabAllocator::new(4096).unwrap();
let _ = allocator.add_slab(SizeClass::Bytes8, va!(0x1000), 0);
§Safety

An accepted base must identify exclusive mapped writable slab memory of the exact requested span, aligned to that span. Keep this memory valid until it is returned, or until all cache operations, slots, and remote producers end.

Source

pub unsafe fn dealloc( &mut self, object: NonNull<u8>, layout: Layout, ) -> SlabDeallocResult

Releases an object through its owning allocator.

Each size class retains at most one empty slab. When another slab of that class becomes empty, it is removed and returned through SlabDeallocResult::FreeSlab with its exact page count.

§Safety

The pointer must be a live allocation from this allocator, with its original allocation layout. Release it exactly once and serialize this call with the allocator’s other operations. Remote frees use Self::remote_free_object.

Source

pub unsafe fn owner_cpu( object: NonNull<u8>, layout: Layout, page_size: usize, ) -> AllocResult<u16>

Returns the logical CPU identifier that owns an allocation.

Requires only the object address, its original allocation layout, and the hardware page size, so it works from any CPU and borrows no allocator state. A kernel typically compares the result with the current CPU to choose between a local and a remote free. The slab size for the layout determines which address bits to mask off, so no header is scanned to find the owner.

An unsupported layout or page size returns AllocError::InvalidParam before memory is accessed.

§Safety

The pointer must identify a live allocation with its original allocation layout and hardware page size. Slab memory must remain valid throughout this call. No incompatible reference to the header may overlap the read of its immutable owner field.

Source

pub unsafe fn remote_free_object( object: NonNull<u8>, layout: Layout, page_size: usize, ) -> AllocResult

Releases an object that belongs to another CPU’s allocator.

Publishes the slot to its slab through SlabPageHeader::remote_free, which needs no access to the owning allocator. The owner drains published slots when a later allocation or deallocation uses that slab. This call does not return slab memory itself.

An unsupported layout or page size returns AllocError::InvalidParam before memory is accessed.

§Safety

The pointer must be a live slot with its original allocation layout and hardware page size. It must be freed once. Slab memory must remain valid until successful publication. The owner may then reuse the slot or reclaim the slab memory immediately. No whole-header reference may overlap publication.

§maybe_non_generic

maybe_non_generic provides the #[maybe_non_generic] attribute macro. It generates a copy of a generic function in which selected generic parameters become ordinary trailing parameters. A const generic becomes a runtime value, and a type generic becomes a value such as a table of function pointers. The copy accepts values that are only known at runtime and is compiled once instead of once per generic argument.

§Usage

Add the crate as a dependency:

[dependencies]
maybe_non_generic = "0.1"

Then annotate a generic function, passing the name of the copy and the parameters to replace:

use maybe_non_generic::maybe_non_generic;

const LEVEL_BITS: [u32; 3] = [9, 9, 10];

#[maybe_non_generic(table_size_dyn, const(LEVEL => level: usize))]
const fn table_size<const LEVEL: usize>() -> usize {
    8 << LEVEL_BITS[LEVEL]
}

assert_eq!(table_size::<2>(), 8192);
assert_eq!(table_size_dyn(2), 8192);

The original function is emitted unchanged, so table_size::<2>() still uses a compile-time level, while table_size_dyn takes the level as its last argument. The copy keeps the visibility, qualifiers, and body of the original, apart from the rewrites of replaced parameters, and copies its attributes by default.

§Replacing type parameters

A replaced type parameter is passed as a value, and calls such as C::now() become calls through its fields, such as (clock.now)(). The function-pointer tables generated by dyn_static_traits have this shape, as the following example shows:

use dyn_static_traits::dyn_static_traits;
use maybe_non_generic::maybe_non_generic;

#[dyn_static_traits(DynClock)]
trait Clock {
    fn now() -> u64;
}

struct BootClock;

impl Clock for BootClock {
    fn now() -> u64 {
        100
    }
}

#[maybe_non_generic(elapsed_dyn, type(C => clock: &DynClock))]
fn elapsed<C: Clock>(start: u64) -> u64 {
    C::now() - start
}

let clock = DynClock::new::<BootClock>();
assert_eq!(elapsed::<BootClock>(40), 60);
assert_eq!(elapsed_dyn(40, &clock), 60);

§Arguments

The name of the copy can be followed by any number of comma-separated arguments:

ArgumentEffect on the copy
const(N => n: T)Replaces the const generic N with the trailing parameter n: T
type(H => h: T)Replaces the type generic H with the trailing parameter h: T
fn(path::f => path::g)Renames calls to the function path path::f
fn(receiver.f => receiver.g)Renames method calls receiver.f(...)
attr(...)Adds the attribute #[...]
dont_copy_attrStops copying the attributes of the original function

A call that passes replaced generic arguments, such as f::<N>(), usually needs a fn(...) rename to the copy of the callee, which then receives the replaced values as trailing arguments.

§Limitations

The macro reports a compile error instead of generating a copy that might still depend on a replaced parameter. For example, replaced parameters cannot remain in type annotations or in generic argument expressions, and the body cannot contain macro invocations or patterns with literals, ranges, or paths. The attribute documentation describes the rewrites, call renaming, attribute copying, and every limitation in detail.
